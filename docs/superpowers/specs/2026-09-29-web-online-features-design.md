# Web 联机聊天与语音设计

**日期：** 2026-09-29
**状态：** 书面规格已批准
**目标：** 在 Web 版恢复小程序版的在线文字聊天与三频道语音，并部署到 `106.53.199.187`。

## 1. 范围与现状

本次只处理 Web 版。保留已有的房间、实时位置同步和本地玩法；让不同玩家能在同一房间文字聊天，并加入全局、猫队或鼠队语音。单机模式没有远程玩家，因此不开放语音。

Web 版已有聊天面板和 `CHAT_MESSAGE` 网络事件，但项目里没有可部署的 relay 服务，语音按钮目前只显示“不支持”。原小程序源码包含三频道 UI 与微信 VoIP 代码；Web 版用浏览器媒体设备和 WebRTC 实现相应体验，不调用微信 API。

目标服务器为 Debian 13、2 vCPU、约 1 GiB RAM，当前只运行 SSH，尚未安装 Web、Node 或 TURN 服务。访问入口使用固定公网 IP；没有提供域名。

## 2. 用户体验

- 游戏内语音按钮打开面板，列出全局、猫队、鼠队三个频道及在线人数。
- 玩家同一时刻只能加入一个频道。频道卡片切换频道；面板显示未加入、加入中、通话中、错误状态，并提供开麦/静音、离开语音和关闭面板操作。
- 加入语音由明确的用户点击触发麦克风授权。点对点音频采用浏览器 WebRTC；本机静音关闭本地音频轨道。离开、结束游戏、退出游戏视图或 WebSocket 断开时关闭本地轨道并清理所有对等连接。
- 单机模式、拒绝麦克风、浏览器不支持、音频播放受限、TURN/网络连接失败等情况均显示可理解的提示；不会中断游戏或文字聊天。
- 文字聊天保留游戏内面板，最多显示最近 8 条消息，单条最长 50 字。消息按纯文本渲染。

## 3. 方案与边界

### 3.1 语音媒体与信令

使用浏览器原生 `getUserMedia` 和 `RTCPeerConnection` 建立音频通话。WebSocket relay 只承担房间成员、频道在线状态和 SDP/ICE 信令，不转发音频。音频通常在浏览器间直连；NAT/防火墙阻止直连时用服务器上的 Coturn 转发加密媒体。

采用网状点对点拓扑，每个语音频道最多 8 名玩家同时通话。网状方案不需要第三方实时音视频 API，适合目前单台小规格服务器。超出此容量需求时应改用 SFU，并重新评估服务器 CPU、内存和带宽；SFU 不属于本次范围。

三频道含义：

| 频道 | 成员 |
| --- | --- |
| 全局 | 同一游戏房间中已加入全局语音的成员 |
| 猫队 | 同一游戏房间、队伍为猫且已加入猫队语音的成员 |
| 鼠队 | 同一游戏房间、队伍为鼠且已加入鼠队语音的成员 |

用户身份继续沿用目前房间协议中的玩家 ID 与队伍资料。服务端以已加入房间的连接作为消息身份来源，并检查频道队伍与容量。由于当前游戏没有账号认证，房间口令和客户端队伍资料不是防恶意伪造的身份凭证；队伍隔离是面向正常游戏客户端的应用层规则。

### 3.2 房间 relay 与聊天

新增 Node WebSocket/HTTP 服务，放在独立 `server/` 目录，不再依赖小程序项目中的 `node_modules`。服务端为每条连接记录游戏房间、玩家 ID、名称、队伍和当前语音频道。

- `CHAT_MESSAGE` 只转发给同一游戏房间的其他玩家。服务端验证发送者来自已加入连接、要求文本内容、限制为 50 字并做发送速率限制。
- 聊天名称和正文在前端以文本节点显示，不拼接为 HTML。
- 新增语音加入、离开、频道名单与信令消息。服务端从连接状态确定发送者，不信任客户端传来的伪造 ID；仅将信令发给同房间、同频道的目标连接。
- 新加入频道的玩家取得当前成员名单；现有成员收到加入/离开事件。对等连接由稳定的玩家 ID 排序确定唯一发起端，避免双方同时创建 offer。
- 每频道最多 8 人。满员时拒绝加入并在 UI 提示。
- WebSocket 关闭、房间离开或页面离开时移除语音成员并通知其他端；空房间从内存移除。服务重启会结束在线房间，不保存聊天记录、位置或语音媒体。
- WebSocket 最大消息尺寸、允许的消息类型、加入状态和信令目标均由服务端校验。通过反向代理访问时只公开 HTTPS/WSS 入口。

### 3.3 TURN 凭证

Coturn 使用服务端私密共享密钥签发有效期约 1 小时的临时凭证。客户端经同源 HTTPS `/api/ice-config` 获取 ICE/STUN/TURN 配置，前端不包含长期 TURN 密钥。Coturn 配置固定监听 UDP/TCP 3478，并限定 UDP relay 端口范围 `49160–49200`。TURN 账号密钥仅以服务环境变量配置，不提交到仓库。

## 4. 部署架构

```text
Browser
  ├─ HTTPS ──────────────── Nginx ── static Web files
  ├─ WSS /ws ────────────── Nginx ── Node relay (127.0.0.1)
  ├─ HTTPS /api/ice-config ─ Nginx ── Node relay
  └─ WebRTC audio ───────── peer browser, with Coturn fallback
```

- Nginx 提供 Web 静态文件、HTTPS 与 WSS 反向代理；Node relay 只监听 loopback，通过 systemd 持续运行。
- 页面默认指向 `wss://106.53.199.187/ws`，服务器地址仍可由用户修改。
- 浏览器麦克风需安全上下文。没有域名时，使用 Let’s Encrypt IP 地址证书；IP 证书为短期证书，需自动续签并在续签后重载 Nginx。Certbot 至少使用支持 IP 与 webroot 的 5.4 版本。
- 入站需要 TCP 80/443、UDP/TCP 3478 与 UDP 49160–49200。操作系统防火墙可由部署配置；若云厂商安全组另有限制，需要在云控制台放行对应规则。
- 只需要安装 Nginx、Node.js、Certbot、Coturn 及其运行配置，不部署数据库或第三方 SaaS。

## 5. 错误处理与隐私

- 麦克风授权失败、没有输入设备、连接建立失败或频道满员：保持游戏和文字聊天运行，显示原因，用户可重试。
- 服务器连接中断：关闭本地语音并清理连接；恢复后要求玩家手动重新加入，以免未明确同意时自动开麦。
- 关闭语音面板只收起 UI，不退出频道；“离开语音”才会离开频道。
- 不录制、存储或上传音频到业务服务。通过 Coturn 的媒体仍由 WebRTC 加密。
- 页面只使用 HTTPS；WebSocket 只使用 WSS。短期证书续签失败应能从 Certbot 与 Nginx 日志诊断。

## 6. 验收标准

1. 访问 `https://106.53.199.187/` 时证书有效，网页静态资源和定位功能在安全上下文中可用。
2. 两个客户端连接默认 WSS 地址后能加入同一房间，互相收发文字；第三个房间不会收到这些消息。
3. 两个客户端加入同一语音频道后双向听到音频；不同队伍频道之间听不到音频；全局频道成员彼此可听。
4. 面板人数、加入/切换/离开、静音状态正确；结束对局或断开后麦克风轨道停止、房间人数更新。
5. 拒绝麦克风、语音频道满员或无法连接时有提示，游戏和文字聊天仍可继续。
6. 服务重启后 systemd 自动拉起；证书续签定时器和 Nginx reload hook 已配置。

## 7. 实施验证

- 检查 Web 资源、健康端点、HTTPS 证书和 WSS 握手。
- 用至少两个客户端检查房间聊天、三频道成员同步、频道隔离、静音、离开和实际音频；同时观察拒绝麦克风时的降级路径。
- 使用 ACME staging/续签 dry-run 验证自动续签流程，并确认正式证书 reload hook 指向 Nginx。
- 不要求持久化语音房间状态或聊天历史。
